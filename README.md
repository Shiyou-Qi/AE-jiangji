# aeback 官网

Premiere Pro / After Effects 工程降级服务的官方网站。
产品结构与视觉基调对标 zerobalanced.com，但**站内没有任何支付入口**。

技术栈：Next.js 16（App Router）+ React 19 + 手写 CSS，**零 UI 库依赖**。

两条产品线的转换引擎形态不同，这一点决定了整个站点的架构：

| 产品线 | 输入 | 引擎 | 处理位置 |
| --- | --- | --- | --- |
| Premiere Pro | `.prproj`（gzip XML） | 自研 Node 引擎（`../prpro-downgrader`） | 服务端调用 |
| After Effects | `.aep`（RIFX 二进制） | 站点内置的 wasm 内核（`public/wasm/`） | **浏览器内** |

## 0. 对外呈现的三条硬规则

这三条贯穿全站，改任何页面/组件时都要守住，每条都有测试守着：

1. **不展示处理过程。** 转换结果只呈现用户关心的四件事：版本变化、文件大小、耗时、下载。
   引擎的逐条日志、处理明细、内部计数，一律不出服务端、不上页面。
   Pr 侧连 `logs` / `srcSchema` 字段都不再返回给浏览器（`app/api/convert/route.js`）。
2. **不解释实现原理。** 页面文案里不允许出现实现层词汇（对象图、规则、校准、RIFX、
   结构代号、内核、chunk 名……）。说人话：能降、会丢什么、怎么验证。
3. **不出现颜色渐变。** 全站只用实色：底色、描边、实色块。渐变文字、光晕球、
   紫蓝青过渡一律禁止 —— 它们是「一眼 AI」的来源。

守这三条的是 `npm run test:noleak`（扫仓库 + 扫 14 个页面的真实 HTML + 扫接口字段）、
`npm run test:copy`（逐条断言该有的文案在、不该有的文案不在），
以及 `npm run test:flat`（全站渐变扫描）。

### 0.1 视觉体系：实色 + 单一主色

| 角色 | 值 | 说明 |
| --- | --- | --- |
| 页面底色 | `#0a0a0f` | 近黑微冷调；叠一层 44px 的 1px 网格（`body` 的 `background-image`，`fixed`） |
| 卡片 / 面板 | `#161622` | 不透明实色，层次靠 `#1e1e2e` 描边与内高光做，不用毛玻璃 |
| 主色 | `#ff4d00` | **只有一个**：按钮、链接、强调文字、进行中状态都用它 |
| 状态色 | `#00e5a0` / `#ffcc00` / `#ff4a47` | 成功 / 警告 / 危险，只表意，不作装饰 |
| 产品图标 | Adobe 官方 SVG | 底板 `#00005B` + 字形 `#9999FF`，见 `components/AdobeIcons.jsx` |
| 品牌标识 | `public/brand/aeback-lockup.png` | 横向 lockup（图形 + 字标 AEBack），透明底，128px 高 / 约 51KB |
| 站点图标 | `app/icon.png` + `app/apple-icon.png` | 192² 透明底 / 180² 近黑底（iOS 不认透明） |

五条约定：

- **主色是实色，不是渐变。** `--grad` 这个变量名是历史遗留，值已经是单一实色 ——
  于是所有 `background: var(--grad)` 自动变成平涂，不必逐个改。
- **Adobe 图标只用官方取色，不自造。** 深蓝底板直接放在近黑底上会糊成一块，
  所以只额外加了一圈 16% 白的细描边让边界立起来；颜色本身一个字节没动。
- **圆角保留原有体系**（10 / 14 / 20 / 28）。参考站用的是 4–12 的小圆角，我们没跟。
  `.grad-text` 已改名 `.accent-text`（值就是主色，不再做背景裁切）。
- **品牌名写作 `AEBack`**（AE + Back 两段，不是 `AEBBack`）。页面上的写法统一取自
  `lib/site.js` 的 `SITE.brand`，改一处即可；`test/e2e.js` 有一条断言锁住这个写法。
- **品牌标识用位图，不内联 SVG。** 原图自带渐变，内联会撞 `no-gradient` 守卫，位图还能保住
  立体感。生成时把副标题那条（原图 `y≥370`）清掉了 —— header 只有 30px 高，
  副标题缩下去只会糊成一条线；图形与字标按像素定位完整保留。

## 1. 跑起来

Pr 那条线需要先把降级引擎起起来；Ae 那条线不需要，它是纯客户端的。

```bash
# 1) 降级引擎（:8788）—— 只有 Premiere 转换需要它
cd ../prpro-downgrader
node src/server/index.js

# 2) 官网（:3100）
cd ../downgrader-site
npm install
npm run dev            # http://127.0.0.1:3100 → 自动跳 /zh
```

引擎地址可通过环境变量覆盖（默认 `http://127.0.0.1:8788`）：

```bash
ENGINE_URL=https://engine.example.com npm run dev
```

## 2. 页面结构

双语是**真实 URL**，不是前端切换，便于分享与搜索引擎收录。

| 路径 | 作用 |
| --- | --- |
| `/` | 307 → `/zh` |
| `/{lang}` | 首页：首屏、版本跑马灯、关键数字、两大转换器、三步流程、使用场景、问答、结尾号召 |
| `/{lang}/premiere-pro-downgrader` | **真实可用的转换器** + 14 版对照表 + 降级代价说明 |
| `/{lang}/after-effects-downgrader` | **真实可用的转换器**（内嵌，全本地）+ 9 版对照表 + 两条线为何不同 |
| `/{lang}/how-it-works` | 降级会做什么、两种处理方式、可靠性说明 |
| `/{lang}/faq` | 分四组：一般 / 会丢什么 / 文件与隐私 / 收费 |
| `/{lang}/privacy`、`/{lang}/terms` | 法务页 |

`lang ∈ {zh, en}`，`dynamicParams = false`，非法语言直接 404。

两个转换器都是站内原生，**没有任何跳转到外部工具的链接**。

## 3. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/engine` | Pr 引擎是否在线 + 可用的 14 个目标版本（只回 `{key, label}`） |
| `POST` | `/api/convert?target=2021&safe=1` | 请求体是工程字节，返回少量元信息 + 一次性下载 token |
| `GET` | `/api/download?token=…` | 取回降级结果，取一次即销毁 |

After Effects 那条线**不经过任何 API**：内核在浏览器里跑，产物用 `Blob` + `createObjectURL`
在本地生成。这一条有测试守着（见 §6），不是口头承诺。

### 为什么 Pr 是「代理 + 一次性 token」，而不是直接把文件流回去

引擎被刻意设计成**无状态服务**（每个请求只吃「形态 + 图」），因此它可以独立部署、
独立扩容，或者干脆跑在用户自己的机器上。官网只通过 HTTP 与它对话，两边能分别部署。

引擎的二进制端点只能把元信息塞进响应头，长度不可控；所以官网走引擎的 `?meta=1` 模式，
一次拿回文件本体，文件在站点侧暂存（最多 6 份、10 分钟过期），前端拿 token 用**原生下载**取回 ——
这样既不占 JS 堆内存，浏览器也能拿到正确的文件名。

**站点只回传用户要看的东西**：`token` / `filename` / `target` / `targetLabel` / `inSize` / `outSize`。
引擎返回里的 `logs` / `srcSchema` / `outSchema` 在服务端就丢掉。

## 4. After Effects 内核（`lib/aep/wasm.js` + `public/wasm/`）

内核是 wasm-bindgen 产物（`aep_core.js` 胶水 + `aep_core_bg.wasm`，约 120 KB）。
它做的是结构化重建，而不是改一个版本号。

> 下面这些是**维护者的工程记录，不是站点文案**。站点侧一个字都不出现（见 §0）。

### 三条必须知道的约束（都是实测出来的）

1. **必须用 `initSync` 手动初始化。** 胶水层的默认导出走 `import.meta.url` + `fetch`，
   在打包环境里不可靠；`initSync` 直接吃 `WebAssembly.Module`，路径完全由我们控制。
   动态 import 的 URL 用运行时变量拼接，避免打包器在构建期试图解析这个 public 资源。
   开发与生产构建都验证过（见 §6）。

2. **调用时要带两个固定的环境标识**（`convert_bytes` 的第 4、5 个参数：host / protocol）。
   取值在二进制里被校验，不合规直接抛 `AEPERR:2001`。
   站点统一传中性的固定常量 `localhost` / `https:`（`lib/aep/wasm.js` 的 `ENGINE_HOST`）——
   它只做取值判断，**没有任何网络请求发出**，转换全部在本机内存完成。
   实测：`aeback.com`、空值、任意域名、非 `http(s)` 协议都会被拒。
   这两个常量一改就要重跑内核测试，产物哈希必须保持不变。

3. **目标版本必须严格低于源版本。**
   `target >= source` 抛 `AEPERR:1001`。所以 UI 先识别源版本，再据此过滤下拉框，
   而不是把 9 个目标一股脑列出来让用户去撞错误。

### 能力边界：为什么 AE 只有 9 个目标版本

这是内核的硬边界，不是站点少列了：

| 目标 major | 结果 |
| --- | --- |
| 9 / 10 / 11 / 12 / 13 / 14（CS4–CC 2017） | `AEPERR:9000` **不支持** |
| 15 / 16 / 17 / 18（AE 2018–2021） | 可用（内核标为 experimental） |
| 19 / 20 / 21 | 内核接受，但输出与源文件相同（Adobe 无这些发行版）→ 站点不列 |
| 22–26（AE 2022–2026） | 可用（stable） |

即 **最低只能降到 AE CC 2018**。`targets_json()` 是唯一真值，站点不额外增删。
想支持 CC 2017 及更早，只有两条路：内核侧实现对应变换，或换自研内核 —— 后者需要
**同一工程在不同 AE 版本的原生导出**作为校准答案，否则无法验证，只能靠猜（那正是本项目一直在拒绝的做法）。

各目标之间的输出差异是**结构级**的，不是改头部几个字节：
同一份 2021 工程降到 15 / 16 / 17，两两之间约 200 万字节不同。

### 版本表：内核是唯一真值

`lib/site.js` 的 `AE_TARGETS` 是**静态镜像**，真值来自内核的 `targets_json()`。
留这份镜像只是为了让版本对照表能在服务端直接渲染（不必等浏览器加载内核）。
`test/aep-core.test.mjs` 有一条断言强制两者完全一致 —— 内核升级而站点忘改，测试直接失败。

major 编号不是简单递增：AE 2018–2021 是 `15–18`，AE 2022 之后跳到 `22`。
这是 Adobe 自己的编号方式，不是我们的映射（页面上不展示这一列）。

### 错误码 → 站点文案

| 内核错误 | 站点 key | 含义 |
| --- | --- | --- |
| `AEPERR:1001` | `E_TARGET` | 目标版本非法（含 ≥ 源版本） |
| `AEPERR:1002` | `E_FORMAT` | 文件格式不支持 |
| `AEPERR:1003` | `E_VERSION` | 版本识别失败 |
| `AEPERR:1005` | `E_REBUILD` | 重建失败 |
| `AEPERR:2001` | `E_ENV` | 环境标识校验不通过 |
| `AEPERR:9000` | `E_UNKNOWN` | 其他（含不支持的目标版本） |

## 5. 值得一提的实现细节

- **双语内容集中在 `lib/content.js`**，`zh` / `en` 结构完全一致，页面只按 key 取值、不判断语言。
  新增文案只改这一个文件。`npm run test:content` 会逐条比对两侧的叶子路径，不对称就报错。
- **Pr 的版本表不写死在前端**：下拉框直接问引擎要；引擎离线时回落到静态表，页面仍然可用（只是转不了）。
- **隐私声明的粒度是分开的**。AE 全本地、文件不上传；Pr 走服务端引擎。两者不能混为一谈，
  所以隐私页、问答、页脚都分别写清楚，没有用一句笼统的「我们不保存你的文件」盖过去。
- **「稳健模式」是产品功能，不是实现细节。** Pr 侧的 `safe=1` 会跳过保守规则，
  文案只说「优先保证结果能打开，必要时少转换一些内容」，不提规则体系。
- **中文标题的断行是设计的一部分**。浏览器默认允许在任意汉字间断行，会把「能打开」
  拆成「能打 / 开」。`globals.css` 在 `min-width: 700px` 时对标题启用 `word-break: keep-all`，
  窄屏则交还给浏览器自动折行（否则超长串会溢出）。
- **不透明的卡片**：所有面板用实色 `--surface`，层次靠描边与内高光做，不用毛玻璃，
  也**不用任何颜色渐变**（见 §0.1）。
- **降级代价写在明面上**：产品页专门有一节讲「会丢什么」，并提示交付前先在目标版本里试打开。

## 6. 测试

十套，各自独立可跑（Pr 相关需引擎在 :8788，其余只需站点在 :3100）：

```bash
npm run test:content     # 双语结构对称性（zh / en 逐条路径比对，236 条）
npm run test:copy        # 文案守卫：该有的在、不该有的不在（中英各一遍）
npm run test:noleak      # 泄露守卫：仓库无第三方域名、页面无实现层词汇、接口无内部字段
npm run test:flat        # 平涂守卫：全站不得出现颜色渐变
npm run test:ae          # AEP 内核校准 41 项
npm test                 # 接口与页面 48 项
npm run test:browser     # Pr 真实浏览器流程 17 项
npm run test:browser:ae  # AE 真实浏览器流程 26 项
npm run test:layout      # 9 页 × 5 断点横向溢出扫描 45 项
npm run test:align       # 问答区块居中（7 页 × 3 断点）21 项

npm run test:all         # 以上全部
npm run shots            # 批量生成桌面/移动截图到 out/shots
```

- **`test/no-gradient.mjs`** —— 逐行扫描 `app/ components/ lib/` 里的渐变字样，
  只放行两类：body 的 1px 网格纹理、`mask-image` 的透明度遮罩（遮的是不透明度，不是颜色）。
  另外单独拦 `background-clip: text`（渐变文字）与 SVG 的 `linearGradient` / `radialGradient`。
- **`test/faq-align.mjs`** —— 逐页量问答区块的左右留白，必须相等（±1px），
  且同一区块里的标题与列表要共享同一条中轴。元素"看着没居中"时，只有几何数字说得准。

- **`test/no-leak.mjs`** —— 三层扫描，缺一不可：
  仓库文本（第三方域名）、**渲染后的 HTML**（14 个页面，实现层词汇）、接口返回字段。
  为什么要扫 HTML：客户端组件的文案会随 RSC 载荷进 SSR 产物，只看源码查不出来。
- **`test/copy-audit.mjs`** —— 逐条断言文案的新旧状态。并行编辑同一文件会互相覆盖，
  所以文案改动一律"改完就断言"，不靠肉眼。
- **`test/aep-core.test.mjs`** —— 价值全在三条实证断言：
  ① 内核版本表与站点静态镜像零漂移；② 环境标识的实际放行/拒绝行为正确；
  ③ **2021 → 2018 的输出与「原生 AE 2018 导出的同工程」逐字节完全相同**
  （`sha256 = 854c2d20…64f6`，4071805 字节）。样本取自系统下载目录的真实工程，缺失时明确跳过。
- **`test/browser-flow-ae.js`** —— 在真实 Chrome 里跑完整流程，额外验证两件服务端方案做不到的事：
  下载链接必须是 `blob:`（证明字节在浏览器内生成），整条流程不能有任何写请求（证明文件没上传）。
  最后把浏览器里产出的字节取出来算 sha256，仍要与原生导出一致 —— 覆盖了「上传控件 → React 状态 → Blob」整条 UI 链路。
  另外断言结果卡片里不出现处理明细。
- **`test/e2e.js`** —— 页面可访问性、引擎代理、错误分支、完整「上传 → 转换 → 下载」链路、
  下载内容是不是合法 gzip、token 是否一次性、**把降级结果再喂回引擎**（结构自洽校验），
  以及「不返回日志 / 结构号字段」这类反向断言。
- **`test/layout-audit.js`** —— 扫描每个页面上右边界超出视口的元素。
  响应式 bug 在桌面截图里看不出来，只有收窄视口才会暴露。
  **注意**：`overflow: hidden` 会掩盖溢出，所以它既看 `scrollWidth` 也看逐个元素的矩形。
- **`test/cdp.js`** —— 浏览器测试共用的极简 CDP 客户端（支持 `on()` 订阅事件，用来抓网络请求）。
  零第三方依赖，用系统 Chrome。

### 内核逆向工具（不改内核，只用于调查）

`test/aep-rifx.mjs`（dump RIFX 块树 / 结构 diff）、`test/aep-capability.mjs`
（target 与 host 的接受矩阵）、`test/wasm-anatomy.mjs`（定位数据段与代码里的守卫）、
`test/aep-matrix.mjs`（单维度变量法）。内核是黑盒，所有结论都必须来自这类实测，不能靠推断。

## 7. 部署

静态页面全部预渲染（14 个路由），3 个 API 路由需要 Node 运行时。

```bash
npm run build && npm start
```

- `ENGINE_URL` 指向线上引擎；引擎可部署在 Cloudflare Workers 一类无状态环境。
- **AE 转换器不依赖引擎**：只要静态资源可访问（含 `public/wasm/` 两个文件）就能工作，
  因此它在纯静态托管下也能跑。
- `next.config.mjs` 里的 `/` → `/zh` 跳转是配置级跳转，不依赖页面。
- 务必确认托管环境返回 `aep_core_bg.wasm` 的 MIME 为 `application/wasm`
  （`test/e2e.js` 有一条断言守着）。

### ⚠️ AE 内核的授权问题

`public/wasm/` 里的内核是**第三方专有代码**（编译产物，无源码）。
目前个人/内部使用风险低，但 `aeback` 是要公开发布的站点 ——
**商用前需要确认授权，或者换成自研实现**。这一条在 `/terms` 里没有对外声明，
但它是这个项目里最需要你拍板的技术/法务风险。

**恢复方式**：从那一次提交里把 `app/[lang]/pricing/` 和 content.js 的三块内容取回来即可。
术语上要注意：服务条款里「保留在正式发布时引入付费档位的权利」是法务表述，**不是**定价入口，保留不动。

## 9. 已知限制

- **Pr 转换器**的输入上限是 64 MB（`app/api/convert/route.js` 的 `MAX_BYTES`）。
  这是「文件经 JSON 传输」这一实现方式的代价；超大工程建议用自托管引擎走命令行。
- **站点不展示转换日志**（§0 的规则）。需要看逐条日志时用引擎 CLI
  （`prpro-downgrader` 的 `npm run cli -- --analyze`），那是给维护者的通道。
- **AE 最低只能降到 AE CC 2018**，见 §4 的能力边界。这是内核决定的，站点无法扩展。
- **Ae 的稳定目标只有 2023–2026**。AE 2018–2021 标为实验性：部分复杂工程可能需要人工调整。
  这是内核自己的标注，站点如实呈现，没有美化。
